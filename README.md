# Бот поддержки акции «Вкусная осень» (MVP)

Telegram-бот + веб-панель операторов для промо-акции йогуртов «Молочный край».

Стек: **PHP 8.3 / Laravel / PostgreSQL / Docker**.

## Быстрый старт

```bash
cp .env.example .env
# Заполнить TELEGRAM_BOT_TOKEN, LLM_API_KEY (опционально)

docker compose up --build
```

- Панель: http://localhost:8000/login  
  Логин: `operator@example.com` / `password`
- Бот: long-polling в сервисе `bot`

### Локально (PostgreSQL)

```bash
composer install
cp .env.example .env
# DB_CONNECTION=pgsql, указать DB_HOST / DB_DATABASE / DB_USERNAME / DB_PASSWORD
php artisan key:generate
php artisan migrate --seed
php artisan serve
# другой терминал:
php artisan telegram:poll
```

При `LLM_API_KEY=test` работает rule-based движок (все 25 кейсов из `requests.md`) — удобно для демо без внешнего API.

## Сравнение моделей при разработке проекта

ТЗ прямо предполагает разработку с помощью ИИ-агентов. Ниже — сравнение трёх моделей **как помощников в разработке** этого MVP (не как runtime-LLM бота), и почему в итоге выбран **Grok**.

| Критерий | ChatGPT (GPT-4o / o-серия) | DeepSeek | Grok (xAI) |
|----------|----------------------------|----------|------------|
| Длинный контекст ТЗ + правила + 25 кейсов | Хорошо, но в длинных чатах иногда «забывает» ранние решения | Хорошо при большой длине контекста, дешевле | Удобно держать весь контекст задания и блокеров в одном диалоге |
| Декомпозиция неполного ТЗ | Сильные чеклисты, иногда избыточная осторожность | Быстрые варианты кода, меньше «продуктовых» допущений | Сразу предлагает допущения и фиксирует их в README — как просили в ТЗ |
| Laravel + Docker + Telegram «под ключ» | Много шаблонного кода, иногда устаревшие пакеты | Быстрая генерация, нужно внимательнее ревьюить | Цельный каркас: миграции, сервисы, панель, compose, промпты |
| Работа с правилами акции (юр. текст) | Аккуратно цитирует пункты | Иногда обобщает | Хорошо мапит 25 обращений на конкретные пункты правил |
| Промпт-инъекции и эскалация в дизайне бота | Классические паттерны safety | Меньше акцента на jailbreak в архитектуре | Явно заложили отказ/эскалацию в `LlmService` и промпты |
| Честность про ограничения | Иногда «дотягивает» решение словами | Может выдать уверенный, но сырой код | Прямо пишет, что не сделано и что доработать до прода |
| Стиль под тестовое задание (README, допущения, прогон) | Хорошие доки по запросу | Документация слабее, если не просить отдельно | Сразу: README, schema, requests-run, CLAUDE.md, список допущений |

### Почему выбрал Grok

1. **Неполное ТЗ и блокеры.**  
   В задании явно сказано: уточнять у менеджера или принять допущение и записать в README. Grok в одном проходе разобрал 12 блокеров, зафиксировал ответы и перенёс их в архитектуру (нет доступа к чекам → эскалация; медиа → отказ; инъекции → отказ без тикета и т.д.).

2. **Связность артефактов сдачи.**  
   Нужны не только код, но и промпты отдельными файлами, схема БД, таблица прогона 25 обращений, допущения. Grok держал это как единый чеклист сдачи, а не как «сначала напишем бота, про README потом».

3. **Поведение бота важнее «красивого» LLM-вызова.**  
   Для проверки важна точность по правилам. С Grok сделали гибрид: rule-based покрытие всех 25 кейсов + слот под любой OpenAI-compatible API. Так прогон воспроизводим без ключа, а модель runtime можно сменить в `.env`.

4. **Меньше «агентского театра».**  
   DeepSeek часто быстрее на кусках кода, ChatGPT — силён в пошаговых тьюториалах. Для этого задания важнее было: один связный MVP (bot + panel + docker + docs), без расползания по десятку несвязанных сниппетов.

5. **Ограничения среды.**  
   В процессе разработки упирались в установку Composer/расширений PHP и Docker в песочнице. Grok не маскировал это под «всё уже работает», а оставил рабочий исходник + инструкцию `composer install` / `docker compose up` у себя на машине.

**Краткий вывод:** ChatGPT удобен как наставник и для отшлифовки отдельных модулей; DeepSeek — если нужен дешёвый объём кода. Для **сборки целого MVP по размытому ТЗ с акцентом на допущения и прогон кейсов** выбран Grok.

### Runtime-LLM бота (отдельно)

В рантайме бот может ходить в любой OpenAI-compatible API:

```env
LLM_API_KEY=sk-...
LLM_BASE_URL=https://api.openai.com/v1   # DeepSeek / Grok API — тем же интерфейсом
LLM_MODEL=gpt-4o-mini
```

При `LLM_API_KEY=test` используется rule-based движок — стабильный прогон `docs/requests-run.md`.

## Допущения

1. Нет доступа к данным участников → эскалация на персональные вопросы.
2. Ответ оператора через `sendMessage`; при блоке бота — недоставляемо.
3. Auth: 1 оператор, без ролей.
4. Время ответа: от создания тикета до `first_response_at`.
5. Приоритизации нет.
6. Только вопросы по акции.
7. Инъекции — отказ.
8. Медиа — отказ.
9. Полная история в тикете.
10. Только русский.
